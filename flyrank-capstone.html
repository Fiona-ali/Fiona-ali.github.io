Which content items should an editor review first?

A client-held-out comparison of a metadata-based review ranking with a freshness-and-volume rule. The goal is a careful triage aid—not an automatic refresh decision.

Shaik Fiona AliRefresh / Content Opportunity Scoring16 November 2026

Abstract

Which anonymized content items should an editor review first for a possible refresh? Using the repository’s 30,000-row starter extract (44 columns, 32 client groups), I ranked the 22,006 rows meeting a 100-impression eligibility floor. A Logistic Regression model using nine content metadata fields was evaluated against the Week-4 freshness-and-volume rule on the same fixed client-held-out split. The model reached Precision@50 of 0.720 and average precision 0.632, compared with 0.380 and 0.521 for the rule; the held-out proxy base rate was 0.577. These results support a human review shortlist on this snapshot only: they do not establish future decline, refresh value, or a causal effect.

1. The decision this supports

Editors have limited time to inspect pages that may deserve attention. This experiment asks whether a simple learned ranking can make the top of that review queue more useful than a transparent freshness-and-volume rule.

The unit is one pseudonymized content item. The output is a ranking score. The action is manual review in an authorized internal system. A false positive costs review time; an item missed by the list could be overlooked. Neither score is an instruction to edit, remove, or publish content.

2. Data and scope

30,000starter-extract rows
44columns in the extract
32pseudonymous client groups
22,006eligible rows, 100+ impressions

The analysis uses the anonymized starter CSV checked into the internship repository: one row per content item. The available measures are rolling aggregates over a trailing 90-day period; the target compares the latest 30 days with the preceding 30 days. This CSV contains no calendar timestamp for the snapshot, so exact calendar coverage is unavailable. This paper does not claim to have queried the full hosted warehouse.

Eligibility is defined as impressions_90d ≥ 100. Pseudonymous identifiers are used only to keep client groups apart during validation. They are not model features. The model also excludes the target, label-derived fields, and impression, click, session, position, and engagement measures.

3. Method

Target proxy. A row is labeled “down” when trend_direction == down. This field describes the latest-versus-previous 30-day comparison in the snapshot; it is not a future outcome.

Model. Logistic Regression ranks eligible rows using nine metadata fields: search volume, competition, CPC, word count, character count, content age, days since last update, content type, and main intent. Numeric values use median imputation, missingness indicators, and standardization; categorical values use an explicit missing category and one-hot encoding.

Validation. A fixed GroupShuffleSplit (25% test fraction, seed 42) keeps whole clients out of training. The split contains 17,396 training rows from 22 clients and 4,610 test rows from 8 disjoint clients.

Comparator. The historical Week-4 rule is log1p(impressions_90d) × min(days_since_last_update, 180) / 180. Both rankings use the same held-out rows. Since the 90-day impression total overlaps the target windows, this rule is disclosed as a non-prospective historical comparator, not a leakage-safe estimate of future performance.

4. Results on the same held-out clients

The test proxy base rate is 0.577. Precision@K is the share of rows labeled “down” among the first K ranked rows. Average precision summarizes ranking across thresholds; ROC AUC compares ordering across positive and negative rows.

5. Limitations and honest framing

  • The target describes a trailing comparison; it does not label what happens after a refresh.
  • One fixed grouped split cannot show stability across time, seeds, or all clients.
  • The 100-impression filter limits conclusions to that selected population.
  • The rule comparator includes a 90-day impression measure overlapping the target windows.
  • No experiment measured whether a refresh changes performance, nor were editorial cost and realized value measured.
  • This starter extract does not support claims about the full warehouse or Google’s ranking algorithm.
Claim boundary: this model can be discussed as a directional, decision-support ranking on a specific anonymized snapshot. It cannot be described as proving future decline or the causal value of a refresh.

6. Ranked recommendations

  1. Use the top 50 as a review queue, not an edit instruction. The observed Precision@50 was 0.720 against a 0.577 proxy base rate on one split.
  2. Have an editor verify context internally. Confirm current intent and page state in the authorized system before deciding whether any change is appropriate.
  3. Test prospectively before operational use. Freeze a cutoff, define a non-overlapping future outcome, preserve time and client separation, and compare against a simple baseline on identical rows.
  4. Measure review outcomes. Record editor dispositions and future metrics; set any pause or retraining thresholds only after independent time-window validation.

7. Reproducibility

The notebook uses seed 42, repeats the grouped split, compares both rankings on the same rows, checks the result against the Week-7 metrics receipt, and saves aggregate metrics and the chart. It does not print or commit row-level ranked records.
